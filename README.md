# Remote Control Desk

This is the cleaned source package for the consent-based Windows remote-control
application. The runtime is Python; unrelated Replit TypeScript scaffolding is
not included.

A consent-based Windows remote-control MVP:

- **Single launcher**: asks for one owner-issued login key, detects whether it is a Master or Remote Agent key, and opens the correct panel automatically.
- **Master**: connects to up to 10 Remote Agents using their Screen Keys.
- **Remote Agent**: shows a Screen Key and asks the remote user to approve each connection.
- Screen streaming, scaled mouse/keyboard control, and clipboard synchronization.
- Internet-friendly WebSocket relay included.
- Owner-only Telegram bot for issuing, inspecting, and revoking role-specific login keys.

## Safety model

The Remote Agent is visible, does not hide itself, and never accepts a Master silently. The Master Login Key and Remote Agent Login Key are different server-validated credentials. A Screen Key is generated by the Remote Agent and is valid only while that agent is online. Pairing also requires approval on the remote PC.

The relay stores only SHA-256 hashes of login and Screen Keys. Every app must authenticate online through the relay, and revoking a login key immediately disconnects devices using it. No client-side key or offline bypass is provided. No software can guarantee that a copied executable will never be reverse-engineered; production protection should also use HTTPS/WSS, signed Windows binaries, and host-level access controls.

## Owner Telegram bot and public relay

Host this combined service on a public Python host. It runs the Telegram bot and
WebSocket relay in one process and stores session keys in
`SESSION_KEYS_DB` (default: `data/session_keys.sqlite3`).

Required environment variables:

- `BOT_TOKEN` — Telegram bot token
- `OWNER_TELEGRAM_ID` — owner's numeric Telegram user ID
- `PORT` — public relay port, normally supplied by the host
- `SESSION_KEYS_DB` — optional persistent SQLite path

Start it with:

```bash
python -m pip install -r control_bot/requirements.txt
python -m control_bot.main
```

In Telegram, the owner uses:

- `/newmaster Office Master` to issue a Master Login Key
- `/newagent Office PC 1` to issue a Remote Agent Login Key
- `/panel` to open the owner admin panel
- `/keys` to list active keys and connected-device counts
- `/revoke 1` to revoke a key and disconnect its devices

The Master Login Key is entered only in the Master app. The Remote Agent Login
Key is entered only in the Remote Agent app. After login, the Remote Agent
panel shows a Screen Key; the Master enters that Screen Key to request access.
The Remote Agent user must approve the request.

Use the public `wss://` URL in the app's login screen. Do not expose a plain
`ws://` relay to the internet.

## Local development

### Relay

```bash
python -m pip install -r control_bot/requirements.txt
PORT=8765 python -m relay.server
```

### Desktop app

```bash
python -m pip install -r desktop/requirements.txt
python desktop/app.py --relay ws://127.0.0.1:8765
```

Pass `--session-key` or set `SESSION_KEY` to prefill the login screen. For local
relay testing, create a key using the `KeyStore` or run the combined Telegram
bot. On Windows, run the same app on every PC; the login key determines whether
that copy becomes the Master or a Remote Agent.

For a public deployment, use the TLS WebSocket URL:

```bash
python desktop/app.py --relay wss://your-relay-host.example
```

## Windows packaging

Run `build_windows.bat` or `build_windows.ps1` on a Windows machine with
Python installed. The script creates a private virtual environment, installs
the pinned desktop dependencies, and builds one standalone
`RemoteControlDesk.exe` with PyInstaller. The app asks for the relay URL and
one owner-issued key, detects the key role online, and opens the complete
Master or Remote Agent UI. The Inno Setup script under `installer/` creates a
single installer and shortcut.

From PowerShell:

```powershell
Set-ExecutionPolicy -Scope Process Bypass
.\build_windows.ps1
```

## Production relay

Deploy `relay/server.py` as a WebSocket service and expose it through TLS. Use
the resulting `wss://...` URL in both desktop apps. Do not use an
unauthenticated public `ws://` relay for real users.

## Clean-package boundaries

The old `bot/` directory is a separate Credit Retriever Telegram application
with PostgreSQL and TemporaSMS dependencies. It is not imported by this
Remote Control Desk runtime and is kept outside this package so the two bots
cannot be started accidentally together.

The previous `dist/` server ZIP is a generated release copy of `main.py`,
`relay/`, and `control_bot/`; it can be regenerated from this source. The
`data/session_keys.sqlite3` file is runtime state and is deliberately not
bundled into a clean source release. Preserve it separately when migrating an
existing deployment.
