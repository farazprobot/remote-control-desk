# Remote Control Desk

A consent-based Windows remote-control MVP with an owner Telegram key manager and a WebSocket relay.

## Run & Operate

- `uv sync --locked` — install the pinned Python dependencies into `.venv`
- `uv run python -m control_bot.main` — run the owner Telegram bot and public WebSocket relay together
- `uv run python -m relay.server` — run only the WebSocket relay for local development
- `uv run python -m py_compile relay/*.py control_bot/*.py desktop/*.py` — compile-check the Python source
- Required secrets: `BOT_TOKEN`, `OWNER_TELEGRAM_ID`
- Optional env: `PORT` (defaults to `8765`), `SESSION_KEYS_DB` (defaults to `data/session_keys.sqlite3`)

## Stack

- Python 3.13, uv, Tkinter
- `python-telegram-bot` for the owner-only control bot
- `websockets` for the authenticated relay
- Pillow, PyAutoGUI, and Pyperclip for the Windows desktop client

## Where things live

- `control_bot/main.py` — owner Telegram commands and inline admin panel
- `relay/server.py` — authenticated pairing and session message relay
- `relay/key_store.py` — SQLite-backed role-bound key hashes
- `desktop/app.py` — single Windows launcher with Master and Remote Agent panels
- `installer/RemoteControl.iss` — Inno Setup configuration
- `build_windows.ps1` — Windows PyInstaller build script

## Architecture decisions

- Login keys are role-bound: Master and Remote Agent keys cannot be exchanged.
- Screen keys are generated by the Agent, hashed by the relay, and valid only while connected.
- Pairing always requires explicit approval on the remote PC.
- The relay forwards authenticated messages but does not capture screens or execute commands itself.

## Product

The project provides a visible Windows desktop app for consent-based screen sharing, scaled mouse/keyboard control, and clipboard synchronization. The owner Telegram bot issues and revokes separate Master and Remote Agent login keys and reports connected devices.

## User preferences

The uploaded project is Windows-first for the desktop client; Replit runs the Telegram/relay service.

## Gotchas

- Use `wss://` for an internet-facing relay; plain `ws://` is only for local testing.
- Do not expose login keys in group chats or logs.
- The owner Telegram ID must be numeric and is checked against private chats only.
